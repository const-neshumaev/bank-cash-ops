# ADR 0014. Комплектация кассы: шаблоны, наследование и область настройки

- **Статус:** Принято
- **Дата:** 2026-10-15
- **Контекст задачи:** администрирование операций и валют, доступных на кассе.

## Контекст

ADR 0007 закрепил, что валюты кассы живут в `core`, а ADR 0008 — что список
доступных на кассе операций хранит `operations`. Оба набора были **opt-in**:
пустой набор означал «без ограничений». Настраивать комплектацию приходилось
для каждой кассы отдельно, а дефолтов на уровне банка или отделения не было.
Понадобилось:

1. удобно настраивать комплектацию новой кассы (дефолтный шаблон банка и
   отделения);
2. выполнять настройку не только администратору, но и заведующему отделением —
   в границах доступных ему отделений;
3. видеть в интерфейсе, какой набор реально действует на кассе и откуда он взят.

## Решение

1. **Шаблоны комплектации.** Добавляются шаблоны двух уровней: **банковский**
   (один) и **отделения** (по одному на отделение). Шаблон хранит набор типов
   операций (`operations`, модель `OperationTemplate`) либо набор валют (`core`,
   модель `CurrencyTemplate`). Отдельные шаблоны для операций и валют: каждый
   модуль владеет своими данными (инвариант «данные принадлежат модулю»).

2. **Наследование по иерархии.** Эффективный набор кассы вычисляется
   динамически: своя настройка кассы (если задана) → иначе **ближайший
   определённый** шаблон по пути «отделение кассы → … → корень → банк». Правило —
   **перекрытие**, а не объединение: более близкий шаблон полностью замещает
   дальний. Шаблон отделения действует и на нижестоящие отделения.

3. **Deny-by-default.** Если ни своего набора, ни шаблона нет — кассе не доступно
   ничего. Набор-шаблон, **определённый**, но пустой, означает «запрещено всё»;
   отсутствие шаблона отличается только источником, но не результатом. Это
   изменяет прежнее opt-in поведение (пустой набор = «без ограничений»).
   Поведение при проведении операции и на рабочем месте кассира меняется
   согласованно: и операции, и валюты строк ограничиваются эффективным набором.

4. **Своя настройка кассы — переопределение.** Касса переопределена, если у неё
   есть собственные записи комплектации. Пустой список в API **снимает**
   переопределение (касса возвращается к шаблону); задать «явно пусто» на
   кассе нельзя — для запрета используют пустой шаблон отделения.

5. **Область настройки.** Вводятся права уровня отделения:
   `operations.config.manage.branch`, `core.currencies.config.manage.branch`
   (первое дополняет существующее `operations.config.manage`, второе заменяет
   использование `core.structure.manage` для валют кассы). Держатель
   «банковского» права (`operations.config.manage`,
   `core.currencies.config.manage`) настраивает всё, в том числе банковский
   шаблон. Держатель права уровня отделения — только кассы и шаблоны **доступных
   ему** отделений (по правилам `BranchAccess`, с учётом `include_descendants`);
   банковский шаблон ему недоступен.

6. **Контракт.** `core` расширяется аддитивно: `OrgDirectory` получает
   `accessible_branch_ids` и `branch_ancestor_ids`; `ReferenceDirectory.
   cash_desk_currency_codes` начинает возвращать **эффективный** набор (никогда не
   `None`). Смена семантики последнего метода — вынужденная (прежнее «`None` =
   без ограничений» исчезает), поэтому версия модуля `core` поднимается.

## Обоснование

Динамическое разрешение (а не копирование шаблона в записи кассы) позволяет
менять дефолт в одном месте и сразу видеть эффект на всех кассах без
переопределения. Перекрытие по ближайшему шаблону даёт предсказуемую иерархию
(отделение уточняет банк). Deny-by-default исключает «случайно разрешённое»:
чтобы операция или валюта стали доступны, это должно быть явно задано.
Разделение прав банк/отделение выражает область настройки в терминах каталога
прав, не смешивая её с личными записями доступа.

## Последствия

Положительные:

- Комплектация настраивается один раз шаблоном и наследуется вниз по дереву.
- Интерфейс показывает источник и состав действующего набора.
- Заведующий отделением настраивает свои кассы, не имея доступа к чужим и к
  банковскому шаблону.

Отрицательные и риски:

- Поведение по умолчанию меняется на запрет: после обновления кассы без шаблона
  и без своей настройки становятся неработоспособны, пока администратор не задаст
  комплектацию. Требуется явное действие администратора.
- Семантика `cash_desk_currency_codes` в контракте `core` изменилась (без `None`).

## Отложенные решения

- **Автоматическое назначение прав системным ролям** при поставке (ADR 0012) —
  по-прежнему в плане; в этой задаче права ролям дописываются разовой миграцией.
- **Копирование комплектации между кассами** и массовые операции — при
  необходимости.
