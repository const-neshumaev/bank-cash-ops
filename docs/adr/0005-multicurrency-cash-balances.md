# ADR 0005. Мультивалютные остатки наличных и запрет перерасхода

- **Статус:** Принято
- **Дата:** 2026-10-14
- **Контекст задачи:** контроль наличных денег в кассе в разных валютах.

## Контекст

Программа должна знать, **сколько каких денег в кассе прямо сейчас**, и не давать
выполнять расходные операции, если денег недостаточно. Касса работает с
несколькими валютами (задаётся индивидуально, см. ADR 0007).

Отдельный вопрос — на каком уровне вести остаток: на кассе или на отделении. Сейчас
наличные физически находятся на кассе, но в перспективе возможен учёт по
отделению (хранилищу).

## Решение

1. **Измерения остатка — касса и валюта.** Первая версия ведёт остаток **на
   кассе**; агрегат по отделению — производное представление. Чтобы переход на
   учёт по отделению был дешёвым, место хранения не «вшивается» в проводку:
   оно задаётся ссылкой на справочник, которая сейчас указывает на кассу.
2. **Два уровня данных.** Проводки — **источник истины**; **материализованный
   остаток** хранится для проверки и производительности. Остаток обновляется в
   той же транзакции, что и проводки, и всегда **восстановим** из них; для
   контроля проводится периодическая сверка.
3. **Запрет перерасхода — жёсткий.** После применения всех проводок операции ни
   один остаток регистра `cash` не может стать отрицательным. Иначе операция
   **не проводится** (ошибка). Перерасход не разрешается и по правам:
   специального «override» нет.
4. **Конкурентность.** Строки остатков блокируются (`SELECT ... FOR UPDATE`) в
   **детерминированном порядке** (по касса, затем валюта), чтобы исключить
   дедлоки. Проверка остатка, блокировка и запись — в одной транзакции
   (см. `docs/adr/0002-postgresql-in-development.md`).
5. **Деньги — `Decimal`.** Суммы хранятся с фиксированной точностью; округление
   выполняется по правилам валюты (минорные единицы).

## Обоснование

Остаток по (касса, валюта) — минимально достаточная модель для физического учёта
наличных: он отвечает на вопрос «сколько в кассе» и позволяет запретить
расход сверх наличия. Материализованный остаток нужен, потому что пересчёт суммы
всех проводок на каждую операцию не масштабируется; при этом он остаётся
производным от проводок, поэтому расхождений можно избежать сверкой. Жёсткий
запрет перерасхода отражает физическую реальность: нельзя выдать деньги, которых
нет в кассе.

## Последствия

Положительные:

- Единая точка правды об остатке с быстрой проверкой при проведении.
- Расход сверх остатка невозможен по построению, а не по договорённости.
- Детерминированный порядок блокировок снижает риск дедлоков при параллельной
  работе кассиров.

Отрицательные и риски:

- Материализованный остаток — ещё одна структура, которую надо поддерживать
  согласованной (снимается сверкой).
- Агрегация по отделению — отдельное представление; при переходе на учёт по
  отделению потребуется пересчёт остатков.

## Отложенные решения

- **Учёт по отделению / хранилищу** и операции перемещения наличных между
  кассами (инкассация) — отдельным решением при развитии модели.
