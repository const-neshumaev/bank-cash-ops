# Архитектура модуля printing_standard

Модуль объявляет **базовый набор печатных документов**. Своих таблиц он не имеет:
объявления регистрируются в SPI модуля `printing`, а хранит их `printing`
(см. `docs/architecture-module-printing.md`).

## Что объявляет модуль

| Объявление | Значение |
| --- | --- |
| `PrintDocumentTypeSpec` | Тип печатного документа `cash_receipt` — «Кассовый чек», сквозная по банку нумерация |
| `PrintTemplateSpec` | Шаблоны чеков для покупки, продажи и конвертации валюты |
| `CashReceiptProvider` | Функция переменных подстановки для чеков обмена |

Шаблоны:

- `cash_receipt_currency_purchase` — «Покупка валюты у клиента»;
- `cash_receipt_currency_sale` — «Продажа валюты клиенту»;
- `cash_receipt_currency_conversion` — «Конвертация валюты».

Для каждого шаблона в каталоге `backend/templates/` лежит образец `.docx`.
Команда `sync_print_templates` копирует его в базу, **если банк ещё не загрузил
свой файл**; загруженный файл синхронизация не перезаписывает.

## Переменные кассового чека

Провайдер отдаёт в шаблон данные операции: наименование банка (корень дерева
отделений), отделение и кассу, дату и время, вид операции, суммы и наименования
принятой и выданной валют, применённый курс, номер чека и номер операции, данные
клиента (когда они есть) и комментарий. Полный перечень с описаниями доступен в
интерфейсе «Шаблоны печатных форм» (поле `variables` API `printing`).

## Расширение под банк

Модуль конкретного банка зависит от `printing`, регистрирует в `AppConfig.ready()`
свои `PrintDocumentTypeSpec`/`PrintTemplateSpec` и провайдер переменных. После
этого администратор привязывает шаблоны к типам операций на странице «Типы
операций». Код `printing` при этом не меняется.

## Ключевые точки входа

- Объявления: `modules/printing_standard/backend/declarations.py`
- Провайдер переменных: `modules/printing_standard/backend/providers.py`
- Образцы шаблонов: `modules/printing_standard/backend/templates/`
- Манифест: `modules/printing_standard/module.yaml`
